# 设计检查表（A~G 展开）

> 查漏模式全表过一遍；单个新设计收尾至少过 A/B/C/E。每项给「通过判据」——答不上就是缺口，不是风格问题。

## A 宿主融合（首要痛点）

- 这个机制在堆叠大陆里有没有原生等价表达？（查 `stacklands-language.md` 词汇表）
- 还是平行发明了一套独有交互？平行交互每多一个，玩家学习成本就翻一倍
- 堆叠大陆玩家的肌肉记忆（叠卡 = 干活、开包 = 随机获取）是否被复用？
- **通过判据**：能指出「等价于原版 XX 机制的变体」，或说清为什么必须新造

## B 循环串联

- 产出谁消耗？下一环是哪个机制？
- 消耗产生什么动力，推回捕捉/劳作/配种/Boss 大环？
- 断链信号：产出只能卖钱或堆仓库 = 没有下一环
- **通过判据**：写得出「产出 X → 供 Y 消耗 → 推动 Z」三段话

## C 经济闭环

- 新增产出列 source 表：谁产、速率多少（数值占位也要写行）
- 对应 sink：什么机制回收它（消耗/卖卡/升星吞噬）
- 三条线分别算：**资源**、**金币**、**帕鲁本体**（帕鲁只进不出 = 栏位与心智双重通胀）
- **通过判据**：每个新 source 至少对应一个具名 sink；数值未定就写「占位待调」

## D 进度曲线

- 落在玩家旅程哪一阶段（进岛 → 立足 → 扩张 → 毕业）？
- 解锁门槛与前置是什么？会不会卡死进度（关键帕鲁/蓝图唯一来源不可达）？
- 毕业点之后还有理由玩吗（重复可玩性）
- **通过判据**：能画出一行式的阶段解锁链

## E 交互一致性

- 与已定决策（DECISIONS D-xxx）相容吗？
- 冲突 → 显式提出重开，落盘写 `- 取代：D-xxx`；不许静默漂移
- 与既有卡的行为一致吗？同类卡同类规则，别一张卡一个特例
- **通过判据**：列出受影响的 D-xxx 清单，无未声明冲突

## F 认知负担（双受众）

- 没玩过帕鲁的玩家：卡面/描述能自解释吗？
- 玩过帕鲁的玩家：同名机制的预期会不会落空（如叫「捕捉」却不是打残扔球）
- **通过判据**：每张新卡的规则一句话讲得清

## G 边界与失败态

- 缺料/目标不存在时：卡傻等还是明确提示？
- 满仓/上限时：溢出消失还是阻塞？
- 死亡/丢失：机制依赖的卡没了怎么恢复（对齐 D-013 自动复活口径）
- 跨岛：会不会破坏 I1/I2 隔离不变量
- **通过判据**：每个失败态都有定义行为

## 附：设计三问示范——搬运适性（用户 2026-10-25 实例，结论未定）

示范的是**路径**，不是答案；落点由用户拍板。

1. **玩家目标**：帕鲁搬运 = 产出自动入库，基地「自己转起来」的自动化感（查清单 #6/#1，不猜）
2. **宿主语言**：放置式流水线下，产出直接落在建筑上、随取随用——「转运」环节原生不存在；词汇表里相关词只有叠放与卖卡
3. **差距处置**，选项列举：
   - **A 替代**：不做搬运——玩家目标已被放置式流水线天然达成，搬运是空转环节（四分法里最便宜）
   - **B 适配**：搬运适性改为被动词条（如「自动收拢所在建筑产出」）——保留自动化感，不动交互模型
   - **C 重开 D-011**：帕鲁自主寻活（含搬运、找活）——交互模型大改，必须显式重开决策，评估与放置式劳作的共存/取代关系、监控台类界面在卡牌语言里的替代形态
   - 帕鲁原版的「监控台界面」是界面形态，卡牌语言无对应物，本身不构成独立选项
   ➡️ 按杠杆排序先问 C 的方向（它决定 A/B 是否还成立），再细化。
