# 追问

目标：在动手前解决决策树的关键分支，让「下一步做什么」不再有歧义；不追求穷尽无关分支。

## 文档权限

- 可以读取全部项目文档、代码和环境事实；历史决策只作背景，不得冒充未确认需求。
- 不修改实现文件。
- 约定留记录时，可以更新 `docs/DECISIONS.md` 与 `docs/PLAN.md`。
- 用户明确确认需求结论后，可以将其提炼进 `docs/REQUIREMENTS.md`。只写用户已经决定的目标、约束、不做什么和验收标准，不发明需求。
- 不改 `README.md`、`AGENTS.md`、`DESIGN.md`、`MEMORY.md`、`CHANGELOG.md`。

## 开场

只问两件，用户已经说明过的不问：

1. **强度**（默认 3）
   - 1 浅问：只问会卡住下一步的
   - 2 常规：补齐明显缺口
   - 3 细问：检查目标、约束、隐含假设、取舍（默认）
   - 4 深挖：主动找风险、边界、遗漏
   - 5 拷打：连前提一起挑战
2. **要不要落记录**：默认落 —— 结论写进项目的 `docs/DECISIONS.md`，未决项写进 `docs/PLAN.md`；需求结论经确认后写进 `docs/REQUIREMENTS.md`。未安装 `kang-docs` 时使用本文约定的路径，不依赖其他 skill 才能执行。

## 先查事实，再问决策

- 能用文件和工具查到的（目录结构、已有文档、git 历史、依赖版本、已装工具、代码现状）**自己查完再开口**，不要交给用户。
- **决策归用户**：凡涉及目标、偏好、成本、取舍，必须提出来并等回答，不许替用户决定。必要时给选项和建议，但不要替他选。

## 沿决策树走

- 问题之间是树，不是清单：某些问题的答案决定另一些问题**还要不要问**。
- **依赖顺序**：先问「能改变其他问题答案」的那个节点（杠杆最高的），而不是「听起来最重要」的那个。父节点没定，不往下问子节点。
- **剪枝**：某条被否掉的答案会连带作废整棵子树，明确说出来（「这条作废，不再问」），不要过几轮又问一遍。

## 提问节奏

- **依赖链上的问题必须一问一答**，等回答再继续。
- 同一父节点下、互不依赖、且答案都是简短选择的问题，可以并问，**一次不超过 5 条**。
- 判据是「问题之间有没有依赖」，不是习惯；不能为了达到 5 条而提前问子节点。

每条问题固定三段，并尽量把措辞设计成回答「是」即接受推荐答案：

```
❓ Q1｜问题标题
问题正文。需要时给 A / B / C 选项，选项要具体、可以直接选。
➡️ 建议：推荐哪个 + 一句话理由。
```

## 问什么（按杠杆排序）

1. 真正想解决什么问题（不是「想要什么功能」）
2. 哪些已经定了（不再问，也不许暗中推翻）
3. 哪些还没定
4. 哪些前提只是「默认成立」（显式拿出来验一遍）
5. 用户还没意识到的问题（成本、维护、边界、失败情形）
6. 哪个取舍会改变后续方向

## 每轮收尾

只要仍有未决分支，就写三行：

- **已决**：这轮确定下来的（一句一条）
- **未决**：还剩几个分支、分别是什么（只列标题）
- **下一步**：下一轮要问的方向

未决清单同时是给 AI 自己的账本：长对话里靠它防止走失、重复提问、忘掉已否的分支。没有未决分支时直接进入收尾，不重复账本。

## 停止条件

- 关键分支都有答案，**或**剩余未知已经不足以改变下一步行动 → 停。
- 不为追问而追问，不为凑轮次造问题。
- 用户说停就停，立刻转成「收尾」。

## 收尾与落盘

1. 输出三行总结：**已确定 / 暂未确定 / 下一步**。
2. 用户确认共享理解后，再执行实际任务或修改文档；确认前只做只读调查。
3. 若约定留记录：
   - `docs/DECISIONS.md` 追加每条「结论 + 理由 + 被否方案」，编号取现有最大编号加一；替代旧决策时在新条目写 `- 取代：D-xxx`。
   - `docs/PLAN.md` 追加未决项与待验证假设。
   - 属于需求的结论，先向用户展示将写入的内容，得到明确确认后再写 `docs/REQUIREMENTS.md`。
4. 无法写文件时，输出可直接复制的 Markdown，不谎称已经落盘。

## 反模式

- 一轮超过 5 个问题，或把有依赖关系的问题塞进同一轮
- 问一个自己能查到的**事实**
- 替用户做**决策**（尤其「我建议这样，就这么定了」）
- 只问不剪枝，几轮后开始重复
- 把「都行」「看情况」当成答案收下，而不给具体默认项并请求确认
